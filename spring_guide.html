Ollama + Spring AI
비용 없는 로컬 AI 파이프라인

기존 Docker MDS 환경에 Ollama를 추가하여 OpenAI 없이 완전한 AI 파이프라인을 구성합니다. llama3.2로 상품 추천·리포트 생성, nomic-embed-text로 RAG 검색까지 비용 0원.

기존 Docker 유지
OpenAI API 불필요
Ollama llama3.2
Spring AI 1.0
Spring Batch 5

Ollama 모델 선택 가이드
환경에 따라 모델 크기를 선택하세요. 8GB RAM이면 llama3.2(3B) 충분합니다.
모델용도크기최소 RAM속도(CPU)추천 환경
llama3.2:1b 채팅·추천 ~1.3 GB 4 GB 빠름 개발 PC, RAM 8GB 미만
llama3.2 기본 채팅·추천·리포트 ~2.0 GB 8 GB 보통 개발 PC, RAM 8GB 이상 ★추천
llama3.1:8b 고품질 생성 ~4.7 GB 16 GB 느림 고사양 PC 또는 GPU
nomic-embed-text 임베딩(RAG 필수) ~274 MB 1 GB 매우 빠름 모든 환경
⚠️
llama3.2 첫 다운로드는 최대 30분 소요될 수 있습니다 (네트워크 환경에 따라). 한 번 다운로드하면 ollama_data 볼륨에 영구 저장됩니다.
🔧
설치 단계별 가이드
총 5단계, 약 30~60분 (모델 다운로드 포함)
1
pgvector 이미지 교체 (docker-compose.yml 수정)

기존 postgres:15를 pgvector 포함 이미지로 교체합니다. 볼륨은 유지되어 데이터 손실이 없습니다.

docker-compose.yml — 1줄 수정
postgres:
  image: pgvector/pgvector:pg15   # ← postgres:15 에서 변경
  container_name: mds_postgres
  # 나머지 동일 (볼륨, 포트, 환경변수 그대로)
bash — 컨테이너 재시작 + pgvector 활성화
docker compose up -d --force-recreate postgres

# pgvector 확장 활성화 (1회만)
docker exec mds_postgres psql -U airflow -d airflow \
  -c "CREATE EXTENSION IF NOT EXISTS vector;"

# 확인 — 0.7.x 출력되면 성공
docker exec mds_postgres psql -U airflow -d airflow \
  -c "SELECT extversion FROM pg_extension WHERE extname = 'vector';"
2
Ollama 서비스 시작

docker-compose.ollama.yml 을 override 파일로 추가하여 Ollama를 기존 스택과 함께 실행합니다.

bash
# Override 파일로 Ollama만 추가 기동
docker compose -f docker-compose.yml -f docker-compose.ollama.yml up -d ollama

# 상태 확인
docker ps | grep ollama

# Ollama API 동작 확인
curl http://localhost:11434/api/tags
✅
{"models":[]} 응답이 오면 Ollama 서버 정상 실행. 아직 모델이 없으므로 빈 배열이 정상입니다.
3
모델 다운로드 (약 2.3GB, 시간 소요)

자동(init 컨테이너) 또는 수동 중 선택하세요. 터미널에서 다운로드 진행률을 실시간으로 확인할 수 있습니다.

방법 A — init 컨테이너로 자동 다운로드
# 별도 터미널에서 실행 (진행률 확인)
docker compose -f docker-compose.yml -f docker-compose.ollama.yml \
  up ollama-model-init

# 완료 후 설치 확인
docker exec mds_ollama ollama list
방법 B — 실행 중인 컨테이너에서 수동 다운로드
docker exec -it mds_ollama ollama pull llama3.2
docker exec -it mds_ollama ollama pull nomic-embed-text

# 저사양 PC라면 1b 모델 사용
# docker exec -it mds_ollama ollama pull llama3.2:1b
방법 C — 로컬 Ollama (Docker 없이)
# Windows: https://ollama.com/download 에서 설치 후
ollama pull llama3.2
ollama pull nomic-embed-text
# application.yml base-url 은 그대로 http://localhost:11434
4
analytics 스키마 + Spring Batch 스키마 생성
bash — analytics 스키마 생성
docker cp scripts/analytics_schema.sql mds_postgres:/tmp/
docker exec mds_postgres psql -U airflow -d airflow \
  -f /tmp/analytics_schema.sql

# 확인
docker exec mds_postgres psql -U airflow -d airflow \
  -c "\dt analytics.*"
ℹ️
Spring Batch 메타 테이블은 spring.batch.jdbc.initialize-schema=always 설정으로 Spring Boot 앱 시작 시 자동 생성됩니다. 별도 SQL 실행 불필요.
5
Spring Boot 앱 빌드 & 실행
bash — 빌드 및 실행
cd weather-commerce-ai

# Gradle Wrapper 생성 (최초 1회)
gradle wrapper --gradle-version 8.10

# 빌드
./gradlew build -x test

# 실행 (로컬 모드: Docker 서비스에 localhost로 연결)
./gradlew bootRun

# 또는 JAR 직접 실행
java -jar build/libs/weather-commerce-ai-1.0.0.jar

# Docker 내부에서 실행할 때
java -jar build/libs/weather-commerce-ai-1.0.0.jar \
  --spring.profiles.active=docker

API 레퍼런스
모든 API는 localhost:8090 기준, JSON 응답
MethodEndpoint설명예시 파라미터
GET /api/recommend 고객 맞춤 AI 상품 추천 ?city=Seoul&customerId=1
GET /api/recommend/anonymous 날씨 기반 익명 추천 ?city=Busan
POST /api/chat RAG 날씨-매출 Q&A {"question":"비 올 때 잘 팔린 상품은?"}
POST /api/chat/city 도시 필터 RAG Q&A {"question":"...", "city":"Seoul"}
GET /api/report AI 날씨-매출 인사이트 리포트 ?days=7
GET /api/report/city 도시별 리포트 ?city=Incheon
POST /api/batch/run/weather-analysis 날씨-매출 분석 배치 수동 실행 –
POST /api/batch/run/embedding-index 임베딩 인덱스 갱신 수동 실행 –
curl — API 테스트 예시
# 1. 서울 날씨 기반 고객 1번 추천
curl "http://localhost:8090/api/recommend?city=Seoul&customerId=1"

# 2. RAG Q&A
curl -X POST http://localhost:8090/api/chat \
  -H "Content-Type: application/json" \
  -d '{"question":"비 오는 날 어떤 상품이 잘 팔렸어?"}'

# 3. 7일치 인사이트 리포트
curl "http://localhost:8090/api/report?days=7"

# 4. 배치 수동 실행 (임베딩 인덱스 갱신)
curl -X POST http://localhost:8090/api/batch/run/embedding-index
⚙️
배치 Job 설명
두 Job이 자동으로 스케줄 실행됩니다. 수동 트리거도 가능합니다.
Job 1 — weatherAnalysisJob
스케줄: 매일 01:00
Reader: weather.weather_data + raw.orders JOIN SQL
Processor: 로깅 및 데이터 검증
Writer: analytics.weather_sales_corr UPSERT

도시 매핑: Seoul→서울, Busan→부산 등
CASE 구문으로 한/영 도시명 JOIN
Job 2 — embeddingIndexJob
스케줄: 6시간마다
Reader: analytics.embedding_log 기준 미처리 날씨 데이터
Processor: WeatherData → Document 변환
Writer: VectorStore.add() → pgvector 저장

중복 방지: embedding_log 테이블로 처리 이력 관리

트러블슈팅
❌ "connection refused" — Ollama에 연결 안 됨
docker ps | grep ollama로 컨테이너 실행 여부 확인.
curl http://localhost:11434/api/tags로 API 응답 확인.
포트 충돌 시 docker-compose.ollama.yml에서 11435:11434로 변경하고 application.yml의 base-url도 수정.
❌ "model 'llama3.2' not found" — 모델 로드 실패
docker exec mds_ollama ollama list로 설치된 모델 확인.
없다면 docker exec -it mds_ollama ollama pull llama3.2 재실행.
저사양이라면 llama3.2:1b를 사용하고 application.yml의 chat.model도 변경.
❌ RAG 답변이 "데이터 없음" 또는 엉뚱한 답변
임베딩 인덱스 갱신 먼저 필요: POST /api/batch/run/embedding-index
SELECT COUNT(*) FROM public.vector_store로 인덱스 데이터 수 확인.
Airflow weather_etl_pipeline이 실행되지 않았다면 날씨 데이터 자체가 없음.
❌ Spring Boot 시작 시 "relation 'analytics.weather_sales_corr' does not exist"
analytics_schema.sql을 아직 실행하지 않은 경우.
docker cp scripts/analytics_schema.sql mds_postgres:/tmp/ && docker exec mds_postgres psql -U airflow -d airflow -f /tmp/analytics_schema.sql
❌ 응답이 너무 느림 (30초 이상)
CPU-only 환경에서 llama3.2(3B)는 첫 응답까지 10~30초 소요될 수 있습니다.
해결책: llama3.2:1b로 변경 (application.yml), 또는 GPU 설정(docker-compose.ollama.yml NVIDIA 섹션 주석 해제).
또는 응답 timeout을 application.yml에서 늘리세요.
💡
OpenAI로 전환하고 싶을 때:
build.gradle에서 spring-ai-ollama-spring-boot-starter → spring-ai-openai-spring-boot-starter 로 변경, application.yml에서 Ollama 설정 제거 후 spring.ai.openai.api-key 추가만 하면 됩니다. 서비스 코드 변경 없음.
