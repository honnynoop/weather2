설치 단계별 가이드
총 4단계, 약 5분 소요 (컨테이너 재빌드 없음)
1
OpenWeatherMap API 키 발급

openweathermap.org 에서 무료 계정을 만들고 API 키를 발급받습니다.

ℹ️
무료 플랜: 1,000 calls/day, 60 calls/minute
4개 도시 × 시간당 1회 = 96 calls/day → 무료 플랜으로 충분합니다.
신규 발급 키는 활성화까지 최대 2시간 소요될 수 있습니다.
API 키 발급 경로 
1. https://openweathermap.org → Sign Up (무료)
2. 상단 메뉴 → My Profile → API Keys 탭
3. API key 열에서 복사
   예: a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4

# 키 동작 테스트 (브라우저 또는 curl)

스크립트가 수행하는 5가지 작업:
① 컨테이너 상태 확인
mds_postgres, mds_airflow_web 실행 중인지 검사
② weather 스키마 생성
weather_init.sql을 mds_postgres에서 실행
③ DAG 파일 배포
./dags/ 폴더에 weather_etl_dag.py 복사
④ HTTP Connection 등록
weathermap_api → api.openweathermap.org
⑤ Airflow Variable 등록
openweather_api_key, weather_cities → Airflow DB에 암호화 저장

🔑 핵심 설계 원칙: Airflow Variable 사용

weather_etl_dag.py — Variable 활용
from airflow.models import Variable

# API 키를 코드에 하드코딩하지 않음 → 컨테이너 재빌드 불필요
def _get_api_key() -> str:
    return Variable.get("openweather_api_key")

# 도시 목록도 Variable로 관리 → UI에서 언제든 변경 가능
def _get_cities() -> list[str]:
    cities_str = Variable.get("weather_cities",
                              default_var="Seoul,Busan,Incheon,Daegu")
    return [c.strip() for c in cities_str.split(",")]

# ✅ 장점: Airflow UI → Admin → Variables 에서 즉시 변경
#          예) Jeju,Suwon,Daejeon 으로 바꾸면 다음 실행부터 적용

🔌 기존 postgres_default Connection 재사용

weather_etl_dag.py — PostgresHook
from airflow.providers.postgres.hooks.postgres import PostgresHook

def transform_and_load(city: str, **context) -> None:
    ti  = context["task_instance"]
    raw = ti.xcom_pull(task_ids=f"extract_weather_{city}")

    # Kelvin → Celsius 변환
    temp_c = round(float(raw["main"]["temp"]) - 273.15, 2)

    # ✅ 기존 환경에서 이미 등록된 postgres_default 재사용
    #    (airflow-init에서 등록: host=postgres, schema=airflow)
    hook = PostgresHook(postgres_conn_id="postgres_default")
    hook.run(
        """INSERT INTO weather.weather_data
           (city, temperature_c, humidity_pct, ...) VALUES (%s, %s, %s, ...)""",
        parameters=(city_name, temp_c, humidity_pct, ...),
    )

weather_etl_dag.py — 동적 태스크 생성
CITIES = _get_cities()   # ["Seoul", "Busan", "Incheon", "Daegu"]

for city in CITIES:
    # Task 1: API 가용성 확인 (reschedule 모드 → 슬롯 점유 없음)
    is_api_ready = HttpSensor(
        task_id=f"is_api_ready_{city}",
        http_conn_id="weathermap_api",
        endpoint=f"/data/2.5/weather?q={city}&appid={api_key}",
        mode="reschedule",   # ← 중요: 대기 중 Worker 슬롯 반납
    )

    # Task 2: JSON 추출 → XCom에 자동 저장
    extract_weather = SimpleHttpOperator(
        task_id=f"extract_weather_{city}",
        response_filter=lambda r: json.loads(r.text),
    )

    # Task 3: 변환 + DB 저장
    transform_load = PythonOperator(
        task_id=f"transform_load_{city}",
        python_callable=transform_and_load,
        op_kwargs={"city": city},
    )

    is_api_ready >> extract_weather >> transform_load  # 체인

Superset SQL Lab 확인 쿼리

🌡️ 최신 도시별 기온
SELECT city, temperature_c,
       humidity_pct, description,
       collected_at
FROM weather.v_latest_weather
ORDER BY temperature_c DESC;
📈 시간별 기온 변화
SELECT hour_bucket, city,
       avg_temp_c, avg_humidity
FROM weather.v_hourly_stats
WHERE hour_bucket >= NOW() - INTERVAL '24 hours'
ORDER BY 1 DESC, 2;
🗓️ 일별 기온 요약
SELECT DATE(collected_at) AS day,
  city,
  ROUND(MIN(temperature_c)::numeric,1) AS low,
  ROUND(AVG(temperature_c)::numeric,1) AS avg,
  ROUND(MAX(temperature_c)::numeric,1) AS high
FROM weather.weather_data
GROUP BY 1, 2
ORDER BY 1 DESC, 2;
💧 습도 vs 풍속 산점도
SELECT city,
  temperature_c,
  humidity_pct,
  wind_speed_ms,
  description,
  collected_at
FROM weather.weather_data
WHERE collected_at >= NOW() - INTERVAL '6 hours'
ORDER BY collected_at DESC;

🛠️
트러블슈팅
❌ apply_weather.sh 실행 시 "컨테이너가 실행 중이지 않습니다"
기존 MDS 스택이 먼저 실행되어야 합니다.
→ docker compose ps 로 컨테이너 상태 확인
→ 모든 컨테이너가 없다면: docker compose up -d 실행 후 1~2분 대기
→ 이후 ./apply_weather.sh YOUR_API_KEY 재실행
❌ DAG 실행 시 "401 Unauthorized" 오류
API 키가 잘못되었거나 아직 활성화되지 않은 경우입니다.
→ 브라우저에서 직접 테스트: https://api.openweathermap.org/data/2.5/weather?q=Seoul&appid=YOUR_KEY
→ 신규 키는 최대 2시간 소요. 기존에 쓰던 키가 있다면 그걸 사용
→ Variable 재등록: docker exec mds_airflow_web airflow variables set openweather_api_key "NEW_KEY"
❌ "relation weather.weather_data does not exist"
weather_init.sql이 실행되지 않은 경우입니다.
→ 수동 실행: docker cp scripts/weather_init.sql mds_postgres:/tmp/ && docker exec mds_postgres psql -U airflow -d airflow -f /tmp/weather_init.sql
❌ "Connection 'weathermap_api' not found"
apply_weather.sh 실행 중 Connection 등록이 실패한 경우입니다.
→ 수동 등록: docker exec mds_airflow_web airflow connections add weathermap_api --conn-type http --conn-host https://api.openweathermap.org
→ 또는 Airflow UI → Admin → Connections → + 에서 직접 추가
❌ DAG 파일이 Airflow UI에 안 보임
Scheduler가 파일을 아직 인식하지 못한 경우입니다.
→ 30초 대기 후 페이지 새로고침
→ Scheduler 로그 확인: docker compose logs airflow-scheduler | tail -20
→ Python 문법 오류 여부: docker exec mds_airflow_web python /opt/airflow/dags/weather_etl_dag.py
❌ Superset에서 weather 스키마가 안 보임
Superset의 DB Connection 설정에서 스키마를 명시적으로 허용해야 할 수 있습니다.
→ Settings → Database Connections → postgres 연결 편집
→ Advanced → ALLOWED SCHEMAS 에 weather 추가
→ 또는 SQL Lab에서 직접: SELECT * FROM weather.weather_data LIMIT 5;
🔁
완전 초기화가 필요할 때 (날씨 데이터만):
docker exec mds_postgres psql -U airflow -d airflow -c "DROP SCHEMA weather CASCADE;"
이후 ./apply_weather.sh YOUR_API_KEY 재실행
