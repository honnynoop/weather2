전체 파이프라인 멀티 프로세스 아키텍처 네트워크 → HTML 수신

파싱 단계

HTML 파싱 → DOM Tree CSS → CSSOM V8 JavaScript 엔진 이벤트 루프

렌더링 단계

Render Tree Layout (Reflow) Paint (래스터화) Composite (GPU) 성능 비용 비교

🌐 브라우저 렌더링 파이프라인

서버 HTML 수신 → DOM/CSSOM → V8 엔진 → Layout → Paint → Composite → 화면 출력 전 과정

🔄 전체 Critical Rendering Path (CRP)

브라우저가 서버에서 HTML을 받아 픽셀로 출력하기까지의 전체 흐름입니다.

🏗 브라우저 멀티-프로세스 아키텍처 (Chrome)

Chrome은 탭 크래시 격리·보안 샌드박스를 위해 여러 프로세스로 분리됩니다. 각 프로세스는 IPC(Inter-Process Communication)로 통신합니다.

📄 HTML 파싱 → DOM Tree 생성

HTML 파서는 바이트 스트림을 받아 토크나이징과 트리 구성 두 단계로 DOM을 만듭니다. 스크립트 태그를 만나면 파싱이 일시 중단됩니다.

파서 블로킹: <script> 태그를 만나면 HTML 파싱이 일시 중단됩니다. async/defer 속성 또는 </body> 직전 배치를 권장합니다.

🎨 CSS 파싱 → CSSOM 생성

CSS도 바이트→문자→토큰→CSSOM Tree 순서로 파싱됩니다. CSSOM은 완전히 구성된 후에만 Render Tree를 만들 수 있어 렌더링 블로킹(Render-Blocking)이 발생합니다.

⚡ JavaScript 엔진 — V8 아키텍처

V8은 AST 생성 → Ignition(바이트코드) → TurboFan(JIT 머신코드) 파이프라인을 사용합니다. 자주 실행되는 Hot Code는 기계어로 최적화됩니다.

이벤트 루프 (Event Loop)

🌳 Render Tree 생성

DOM Tree와 CSSOM Tree를 병합해 실제 화면에 표시되는 노드만 포함하는 Render Tree를 만듭니다. display:none 노드는 완전히 제외됩니다.

📐 Layout (Reflow) — 위치와 크기 계산

Render Tree 각 노드에 대해 정확한 위치(x,y)와 크기(width,height)를 픽셀 단위로 계산합니다. Box Model을 기반으로 합니다.

Layout Thrashing (성능 주의): element.offsetWidth, getBoundingClientRect(), scrollTop 등은 읽는 순간 레이아웃을 강제 계산합니다. 루프 안에서 읽기/쓰기를 반복하면 강제 동기 레이아웃(Forced Synchronous Layout)이 발생합니다.

🖌 Paint (래스터화) — 픽셀로 그리기

레이아웃 완료 후 각 노드를 드로우 명령(Display List)으로 기록하고, GPU 레이어로 분리한 뒤 Skia로 픽셀 비트맵을 생성합니다.

🎮 Composite (GPU 합성) → 화면 출력

페인트된 레이어들을 Compositor Thread가 GPU로 합성하여 Frame Buffer에 기록합니다. Main Thread와 독립적으로 실행되어 스크롤·줌이 빠릅니다.

⚡ 렌더링 성능 — Reflow vs Repaint vs Composite

DOM/CSS 변경이 파이프라인의 어느 단계부터 재실행되느냐에 따라 성능 비용이 크게 다릅니다.

CSS 속성유발 단계설명
width, height, margin, padding, top, left, font-sizeReflow → Repaint → Composite레이아웃 전체 재계산 (가장 비쌈)
color, background-color, visibility, box-shadowRepaint → Composite위치 계산 없이 다시 그림
transform, opacityComposite onlyGPU가 직접 처리 (가장 저렴, 60fps 유지)
will-change: transformGPU 레이어 사전 승격미리 레이어 분리로 애니메이션 준비
애니메이션 황금 법칙: 애니메이션은 transform과 opacity만 사용하세요. Compositor Thread에서 Main Thread 없이 독립 실행되어 JS가 바빠도 끊김 없이 60fps를 유지합니다.
